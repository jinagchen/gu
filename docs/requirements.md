## 2 三个重要边界

任务书写的是严格受限内存，并以“数据集大小的 10%～20%”举例，未明确数据集大小的分母、计量范围和构建阶段规则。因此 10%、15%、20% 是当前团队自测档位，尚不是完整官方评测协议。

三个优化方向不是要求全部实现。当前团队路线计划覆盖缓存、异步预取和写入合并，以读侧优化为主创新线；如可行性验证需要缩减，必须更新范围和实验，不能删掉插入、更新及并发混合负载这些总任务要求。

任务书没有给出绝对 QPS、最大 P99、固定写入可见延迟或写放大阈值。“QPS 提高 30%、P99 降低 20%”只是已有技术方案的内部探索目标，不能宣称是官方门槛或已测收益。

## 3 项目目标与范围

交付一个工作集超过内存的单机动态向量检索引擎，在声明的硬件、数据与负载范围内达到召回要求，提供并发查询、插入与更新，且能用实验解释 I/O 优化的收益和边界。

本轮范围包含 C++ 核心与进程内基准程序、Python 离线评测、存储接口、用户态块缓存、异步读取、增量写入、后台整理、指标、调用示例和复现实验。

暂不纳入：分布式、GPU、完整聊天界面、训练嵌入模型、复杂学习型控制器、生产级鉴权和运维平台。删除接口、复杂元数据过滤、事务组、多个距离度量及跨平台性能保证属于可选增强，不作为当前承诺。逻辑更新和旧版本过滤仍属必做。

任务书举例的 HNSW、io_uring 和 LangChain 不是唯一实现。图检索依赖的版本与可改造性已在[阶段二](stage2-completion.md)通过小数据验证。公开 API 和自有磁盘格式按[阶段三冻结记录](stage3-freeze.md)执行。

## 5 功能和语义默认口径

以下是当前工程默认约定，主办方有不同要求时修订。

### 5.1 数据与查询

初始基线采用单索引固定维度、浮点向量和平方 L2 距离；其他数据类型可以在离线准备阶段显式转换，保存转换说明。若正式数据要求余弦或内积，先统一索引、精排和真实答案的度量，再报告结果。

每个向量有稳定逻辑 ID。查询返回不重复的有效逻辑 ID 和同一度量的距离，排序规则固定。单元验证使用无距离并列的数据；正式数据若存在边界并列，记录并列处理规则，不能用未说明的不同规则比较召回。

K 为正整数。成功查询返回 `min(K, live_count)` 条结果，空索引返回空结果。候选预算内找不全时返回 `search_incomplete`。正式 Recall@10 使用 K=10 且每个评测快照至少有 10 条有效向量。

### 5.2 写入与可见性

insert 对已存在逻辑 ID 返回冲突。upsert 对不存在 ID 插入，对已存在 ID 产生新版本。语义与错误码以冻结的 [API-1.2](interface-contract.md) 为准。

默认采用持久化确认：WAL 达到声明的持久化点，增量与版本视图发布后才向调用方返回成功。组提交可以使用，但不能暗中切换成仅写入进程缓冲就确认。

成功返回后启动的查询须使用包含该版本或其后续版本的快照。检索是近似的，因此“写入可见”不等于“每个近似查询一定返回这个 ID”；小数据的版本探针和动态召回应分别验证可见性与检索质量。

查询过程中发生的更新不改变该查询已固定的数据视图。失败或超时的写入可能存在结果不确定性，调用方通过同一逻辑 ID 核实；不承诺尚未设计的恰好一次语义。

### 5.3 恢复与后台整理

进程故障恢复后，不得遗漏已成功确认的写入；未收到成功响应但完整持久化的写入允许恢复出现，不完整尾记录不能作为有效更新。不能承诺磁盘物理损坏时仍无损恢复。

冻结增量和旧索引仍被查询引用时不可回收。写入在 WAL 同步并发布后确认。`Checkpoint` 成功表示持久化段及清单覆盖至目标序号，回收按冻结的[存储协议](storage-protocol.md)执行。

只有在实测可持续范围内声明写入吞吐。后台处理赶不上新增负载时，限制接入速率或明确返回过载，不允许无限使用内存或磁盘空间掩盖问题。

## 6 评测默认口径

| 项目 | 当前团队自测约定 | 官方状态 |
| --- | --- | --- |
| 数据规模 | 小数据验证，再用超过内存的较大数据及高维嵌入数据 | 正式数据待确认 |
| 内存分母 | 基准开始时有效原始向量载荷字节数，不含图、压缩副本和日志；动态测试期间固定此预算 | 待确认 |
| 内存档位 | 分母的 10%、15%、20%，预算过小不能运行时如实报告失败 | 示例比例，不是完整官方协议 |
| 内存计量 | 被测服务及后台子进程放同一受限域，记录总峰值与分类，页缓存等是否计入按平台实测说明 | 官方范围待确认 |
| 构建 | 单独测量，尽量按同样预算验证；若必须放宽，结果标注且不宣称构建合规 | 是否限内存待确认 |
| 读写比例 | 查询/写入 100:0、95:5、80:20；混合写入默认插入/更新各半 | 团队测试矩阵 |
| 并发 | 1、8、32、64；同时测指定到达速率、排队和过载 | 官方规模待确认 |
| 负载形态 | 均匀、会话热点、热点迁移、突发；合成数据显式标注 | 团队测试矩阵 |
| 时长 | 静态初值预热 60 秒、测量 300 秒；动态至少 30 分钟且跨三轮合并，未满足则延长 | 可在正式实验前登记调整 |
| 重复 | 至少三次，记录种子与波动；正确性和恢复测试不以重复性能替代 | 团队约定 |
| 冷热状态 | 冷启动和稳态分开，说明清理方式及适用存储路径 | 团队约定 |
| 收益门槛 | 有效负载下提供公平对照与消融；绝对 QPS、P99 和写放大暂不虚设 | 官方无数值，团队目标后续登记 |

Recall@10 以逻辑 ID 去重后的结果与对应快照精确 Top-10 的交集大小除以 10，对完整轮次的约定查询集取 `recall_at_k.mean`。失败和拒绝单列且均计零分。工件无效、不完整或需复核时不计分。距离并列按 ID 排序，替代计分规则须在正式实验前登记。详见[评测协议](evaluation-protocol.md#6-查询与答案工件)。

动态精确答案在测量之外对固定快照离线计算，C++ 基准需记录查询对应的快照或可重放序号。不得用初始答案评价更新后的数据，不得让离线计算干扰被测 CPU、内存和 SSD。

延迟从预定请求到达时间计算至完成时间，另报实际执行时间与排队；查询 QPS 和写入 ops/s 分列，报告投递、接受、完成、失败和拒绝数量。写入背压等待计入写入端到端延迟。

同一对比组保持数据、线程、内存、持久化与可见性语义相同，调参后按相近实测召回比较；算法参数固定的消融单独标注。引擎读取请求、设备读取统计、文件写入字节和 SSD 内部写放大不得混为一个指标。

### 2.2 已补充：容量粗算与资源演练，规模化验证留后续

依据：[架构的快照设计与内存分区](architecture.md)。

已建立[容量配置](../configs/stage2-capacity.json)：百万条 768 维原始载荷 3.072 GB，20% 预算 614400000 字节，查询和重建两种预算均求和一致；给出 PQ、图、双代磁盘、增量、影子表、8 查询和 64 在途读取的粗算，要求 D 盘至少 40 GiB 空闲。

已实测小规模依赖构建、加载私有提交，以及旧索引保持打开时新索引全量重建的 Job 峰值；该演练没有实现 Engine 的版本合并或持续写入。百万条全量重建能否在拟定预算运行仍需分区/有界构建验证，不由小样本外推为通过。

阶段二粗算证据已具备；阶段三须将预算模式切换与准入边界落入契约，后续实现再验证实际分配、动态保留代次和大规模资源峰值。

### 2.5 已修正：JSON 数值类型规则

依据：[评测协议的全局 JSON 规则](evaluation-protocol.md)、[静态配置](../configs/examples/static-run.json)。

协议写明“计数”为十进制字符串，但示例中的 max_queries、max_pending_writes、workers、client_queue_capacity 等使用 JSON 数值，未列出有界配置整数的例外。两人分别实现严格解析器时可能产生不兼容。

关闭方式：逐字段明确哪些使用 JSON 整数、哪些使用十进制字符串，同步协议、示例和校验规则。当前“可解析”只证明 JSON 语法有效，不证明完整 schema 一致。

## 下一步与退出条件

1. **B 主责、A 配合：接通最小动态闭环。** 在 WAL 同步后发布可见序号；覆盖确认后可见、重复 ID 的 insert 冲突、upsert 旧版本过滤、已有查询的快照不变。`Get` 验证版本可见性，离线精确答案单独验证检索质量。
2. **A/B：验证恢复。** 进程终止后校验最新 WAL 实际 EOF、历史 WAL 缺尾和 CRC 错误；验证已确认写入可重放、重复打开不重复应用、恢复后序号连续且可续写。失败须保留 `may_have_applied` 语义；暂不启用旧 WAL 自动回收。
3. **A/B：建立可信的混合负载结果。** 接通 C++ 写请求与 EVAL-1.1 真实收据，先跑小规模 95:5 与 80:20；再完成后台合并、跨代次读、写入背压、超内存工作集及 10%/15%/20% 团队自测。未执行的项目继续按[验收矩阵](acceptance-matrix.md)保留。
4. **并行准备初赛交付。** 按 [公开赛程及提交要求](open-questions.md#已核实的赛程与提交信息)核对队伍 GitLab 记录、材料和回执。演示用已验证的静态链路，动态、合并和正式性能只随真实验收更新，附第三方与 AI 使用披露。

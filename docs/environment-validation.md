## 3 远程验证顺序

获得服务器 SSH 登录命令和认证方式后，先进行只读检查：

1. 系统发行版、架构、内核、CPU 配额、内存限额及实际可用资源。
2. 数据所在磁盘、文件系统、空间、挂载与虚拟化信息；区分实例内可见设备和云服务底层介质，不能仅凭设备名称推断是直连 NVMe。
3. C++ 编译器、CMake、构建工具、Git、Python 与依赖。
4. io_uring 是否受内核、容器或权限限制，以及内存限额控制是否可用。

随后在独立项目目录做有界的验证：C++20 编译与链接、Python 数值检查、临时小文件同步读取与 io_uring 功能探针、固定依赖的小数据构建与查询。清理仅限验证程序创建的临时文件，不对已有数据做破坏性测试。

功能探针不代表性能结论。若服务器是虚拟机或使用云盘，报告实际配置、共享资源与波动，说明其对 I/O 实验结论的限制；原生 Linux/NVMe 仍是方案目标，是否满足由实测决定。
